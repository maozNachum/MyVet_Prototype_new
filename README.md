# MyVet

npm i
npm run dev

מערכת מידע מקיפה לניהול מרפאה וטרינרית, בעברית ובכיוון RTL. המערכת מרכזת את עבודת צוות המרפאה ואת השירות ללקוחות: יומן תורים, תיק רפואי, מעבדה, אשפוזים, מלאי, מרפאה דיגיטלית, דוחות ו־VetBot.

> MyVet פותחה כפרויקט גמר המדמה מוצר אמיתי. פעולות רפואיות משמעותיות דורשות אישור אנושי, ותשלום בפורטל הלקוחות הוא תהליך הדגמה בלבד.
קישור לאתר לייב:https://my-vet-prototype-new-6guj.vercel.app/login
קישור לדף נחיתה:https://my-vet-site.vercel.app/

## יכולות מרכזיות

### סביבת צוות המרפאה

- דשבורד תפעולי עם תורים, פניות, בדיקות ומטלות הדורשות תשומת לב.
- יומן תורים יומי, שבועי וחודשי, כולל ניהול זמינות, קיבולת וחסימות.
- ניהול לקוחות וחיות, כולל פרטי זיהוי, תיק רפואי והיסטוריית טיפולים.
- תיעוד ביקורים, חיסונים, בדיקות מעבדה, אשפוזים ומסמכים רפואיים.
- ניהול מלאי, פריטים, התראות מלאי ומחירון שירותים.
- מרפאה דיגיטלית לניהול שיחות, קבצים וקישורי וידאו.
- דוחות ומדדים תפעוליים.
- ייבוא וייצוא תיק חיה בקובצי Excel/CSV, כולל פרטי חיה ורשומות רפואיות נתמכות.

### פורטל לקוחות

- צפייה בחיות המשויכות ללקוח ובמידע הרלוונטי עבורן.
- קביעת תור מתוך השעות הפנויות שהמרפאה הגדירה.
- צפייה בתורים, מסמכים, תזכורות והתראות.
- פתיחת פנייה למרפאה הדיגיטלית ומעקב אחר השיחה.
- ניהול פרופיל ותצוגת חיובים ותשלומים לצורכי הדגמה.

### VetBot ויכולות AI

- עוזר בעברית המותאם לתפקיד המשתמש ולהקשר המסך.
- סיכום תמונת מצב והכוונה לנושאים הדורשים בדיקה.
- פעולות מאושרות מראש, כגון ניהול תורים, מלאי, שיחות דיגיטליות וחסימות ביומן.
- הכנת טיוטות וניווט למסכים בלי לבצע החלטות רפואיות עצמאיות.
- מנגנון fallback מקומי כאשר ספק ה־AI החיצוני אינו זמין.
- צמצום והשחרת מידע רגיש לפני העברת הקשר לשירות AI חיצוני.

חלק מיכולות ה־AI המתקדמות נמצאות בשלבי Preview ובדיקות. יש לאמת אותן בסביבת היעד לפני שימוש ב־Production.

## משתמשים והרשאות

| תפקיד | שימוש מרכזי |
| --- | --- |
| מנהל מרפאה (`clinic_admin`) | ניהול מלא של המרפאה, הצוות, ההגדרות והתפעול |
| וטרינר (`vet`) | טיפולים, תיקים רפואיים, מעבדה ואשפוזים |
| אח/ות (`nurse`) | תמיכה בטיפול, אשפוז, חיסונים ומעקב |
| מזכירות (`secretary`) | לקוחות, חיות, תורים ושירות שוטף |
| בעלים (`owner`) | גישה מוגבלת לפורטל הלקוח ולמידע השייך לו בלבד |

ההרשאות נאכפות גם בממשק וגם בבסיס הנתונים באמצעות Supabase Auth ו־Row Level Security.

## טכנולוגיות

- React, TypeScript ו־Vite
- Tailwind CSS 4
- React Router
- Supabase: Auth, PostgreSQL, RLS, Realtime, Storage, RPC ו־Edge Functions
- Gemini דרך Edge Function של Supabase בלבד
- SheetJS לייבוא ולייצוא Excel/CSV
- Vitest ובדיקות אינטגרציה ייעודיות
- Vercel לפריסת ממשק המשתמש

## ארכיטקטורה בקצרה

```text
React + TypeScript
        │
        ├── Supabase Auth + RLS
        ├── PostgreSQL + RPC
        ├── Private Storage
        ├── Realtime
        └── Edge Functions ── Gemini
```

- הדפדפן משתמש רק במפתח Supabase המיועד ל־Frontend.
- פעולות רגישות ופעולות AI מתבצעות בצד השרת.
- מיגרציות Supabase הן מקור האמת למבנה הנתונים ולהרשאות.
- מסמכים רפואיים נשמרים באחסון פרטי ונפתחים באמצעות קישורים חתומים.

## התחלה מקומית

### דרישות מוקדמות

- Node.js בגרסת LTS עדכנית
- npm
- פרויקט Supabase מוגדר ונגיש

### התקנה והפעלה

```bash
git clone <repository-url>
cd MyVet_Prototype_new
npm install
cp .env.example .env
npm run dev
```

לאחר ההפעלה, Vite יציג את הכתובת המקומית של האתר.

## משתני סביבה

בקובץ `.env` המקומי יש להגדיר:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```


## פקודות שימושיות

```bash

git diff --check
```

## אבטחה ופרטיות

- לכל תפקיד מוגדרת גישה מצומצמת בהתאם לצורך העסקי שלו.
- לקוח אינו יכול לצפות בפרטי לקוח, חיה או תור שאינם שייכים לו.
- קביעת תור על ידי בעלים עוברת דרך פעולה אטומית בצד השרת.
- מידע מזהה ורגיש מושחר לפני פנייה לספק AI, גם בדפדפן וגם ב־Edge Function.
- לוג VetBot שומר metadata בלבד ואינו אמור לשמור טקסט רפואי או תוכן שיחה.
- VetBot אינו מאבחן, קובע מינונים או משנה מידע רפואי ללא אישור אנושי.

למידע מפורט ראו את [תסקיר הפרטיות של VetBot](docs/VETBOT_PRIVACY_DPIA_HE.md) ואת [נוהל ה־Production](docs/PRODUCTION_RUNBOOK_HE.md).

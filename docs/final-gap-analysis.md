# MyVet — Gap Analysis סופי

עודכן: 17.07.2026

סטטוס: **CONDITIONAL PASS לדמו; לא אישור Production**

## P0 — לפני המבחן

### תוקנו

- ברירת מחדל פתוחה של סיכום ביקור.
- היעדר הבטחה לשורות Feature Flag בכל מרפאה.
- רגרסיית הסתעפות בדגלי סיכום לקוח/מעקב שהתגלתה בחבילת הבדיקות.

### נותרו

- אין P0 ידוע בקוד המקומי.
- אם Smoke test ידני של מסך מרכזי נכשל, יש לסווגו מיד כ־P0 ולעצור את מסלול הדמו המתאים.

## P1 — חשוב לאחר המבחן

1. להקים Supabase Preview Branch ולהחיל בו את Migrations שלבים 2–9 לפי הסדר.
2. להריץ בדיקות RLS חיות עם שתי מרפאות, שני וטרינרים, עובד, שני בעלים וחיות סינתטיות.
3. לאמת pgvector, ממד 768, HNSW ו־`EXPLAIN` על שאילתת RAG אמיתית.
4. לפרוס ולבדוק את Edge Functions החדשות עם Secrets של Preview בלבד.
5. לבדוק כל יכולת מול ספק אמיתי ולכייל RAG/OCR לפני הפעלה.
6. לבצע E2E דפדפן מלא ב־desktop וב־mobile, כולל כשל ספק ו־AI כבוי.
7. לאמת ולסגור את ה־drift ההיסטורי של `ai-insights-chat` ושל `insights` בפרויקט החי; קוד Stage 2 מקשיח אותם אך לא הוחל במסגרת משימה זו.
8. להחליף Rate Limiter בזיכרון בפתרון מבוזר לפני עומס אמיתי.
9. להוסיף scheduler מנוטר ל־Retention של הקלטות, תמלולים וקבצים זמניים.
10. להוסיף בדיקות עומס ו־E2E למצלמה, PDF, Google Meet וסליקת תשלום אמיתית כאשר יתווספו ספקים.

## P2 — דרישות Production

- בדיקת חדירה וביקורת הרשאות חיצונית.
- סיווג מאגר, DPIA סופי, ייעוץ משפטי, DPA עם Supabase וספקי AI ועילת העברה מחוץ לישראל.
- החלטת Retention ומחיקה מאושרת, ZDR/אי־אימון ותתי־מעבדים.
- ניטור, התראות, Runbooks לאירועים, רוטציית סודות ו־Audit תקופתי.
- גיבוי, שחזור, Disaster Recovery ותרגיל שחזור.
- בדיקות עומס, זמינות, עלות, quota ו־failover ספק.
- נגישות מלאה ובדיקות שימושיות רשמיות.
- טיפול בתלויות Production שזוהו בעבר (`react-router`, `xlsx`) לאחר בדיקת תאימות; אין להריץ `audit fix --force` ללא תכנון.

## החלטות מוצר שממתינות

- האם וכיצד לאפשר Q&A לבעלים; אין להחליש הרשאות כדי להפעילו.
- נוסח והיקף הסכמה להקלטה/תמלול, משיכת הסכמה ושמירת קבצים.
- מי רשאי לשחרר סיכום לקוח ותזכורת, ומהו נוהל ביטול שחרור.
- איכות מינימלית נדרשת ל־OCR ול־RAG לפני שימוש קליני.

## מסקנה

ליבת המוצר מתאימה להצגה כאשר משתמשים בנתוני דמו ומותירים את היכולות החדשות כבויות. השלמת P1 נדרשת לפני הצגת שלבים 3–8 כיכולות עובדות מקצה לקצה; השלמת P2 נדרשת לפני שימוש Production אמיתי.

# תסקיר השפעה על הפרטיות — VetBot

עודכן: 15.07.2026  
סטטוס: מסמך הנדסי לקראת פריסה. אינו מחליף ייעוץ משפטי או קביעה של ממונה הגנת פרטיות.

## 1. מטרת המערכת והיקף העיבוד

VetBot מסייע בתעדוף תפעולי, סיכום מידע, ניסוח טיוטות והכוונה בתוך MyVet. הוא אינו מוסמך לקבל החלטה רפואית סופית, לקבוע אבחון או מינון, לשלוח הודעה, לעדכן רשומה או לבצע הזמנה באופן עצמאי.

זרימת המידע:

1. המסך בונה הקשר מצומצם לפי תפקיד המשתמש.
2. מנגנון מקומי מפיק תדריך יזום ללא העברה לספק AI.
3. רק כאשר המשתמש שואל את VetBot, הקלט עובר הסרת מזהים בדפדפן.
4. פונקציית השרת מאמתת משתמש ותפקיד ומבצעת הסרת מזהים נוספת.
5. כלי קריאה בלבד מחזירים ספירות ונתונים תפעוליים ללא שמות או פרטי קשר.
6. לספק המודל נשלחים הקשר מצומצם, תוצאות הכלים והשאלה לאחר השחרה.
7. התשובה נבדקת ומושחרת שוב לפני הצגתה.
8. נשמר לוג מטא־דאטה בלבד; לא נשמרים השאלה, התשובה או תוכן רפואי.

## 2. מידע שנחסם לפני עיבוד חיצוני

- שם בעלים, לקוח, איש צוות או שולח.
- תעודת זהות ומזהים פנימיים.
- כתובת, טלפון ודואר אלקטרוני.
- פרטי תשלום, מספרי כרטיס, סודות וסיסמאות.
- מספר שבב, קישורים, כתובות קבצים וקישורי שיחות וידאו.
- שדות מלאים המזוהים לפי מפתח רגיש, גם אם התוכן אינו תואם תבנית מוכרת.

מידע רפואי על בעל החיים נשלח רק בצורה הנדרשת לפעולה ולא יחד עם מזהים ישירים של אדם. יש להביא בחשבון שגם מידע נטול מזהים ישירים עלול לאפשר זיהוי עקיף; לכן יש להגביל כמות, היסטוריה והקשר.

## 3. התאמה לעקרונות הדין הישראלי

| דרישה/עיקרון | יישום ב־MyVet | אימות נדרש לפני ייצור |
|---|---|---|
| יידוע בעת איסוף מידע לפי סעיף 11 | דף פרטיות ציבורי, גילוי בכל חלון VetBot וקישור מטופס ההרשמה | להשלים שם משפטי ופרטי קשר אמיתיים של בעל השליטה |
| שימוש רק למטרה שנמסרה | הנחיית מערכת מגבילה לשירות המרפאה; אין אימון מקומי או שימוש שיווקי | לאשר מטרות במסמך הגדרות המאגר ובהסכם הספק |
| צמצום מידע ובדיקה שנתית של מידע עודף | רשימת חסימה, הקשר מצומצם, זיכרון לסשן בלבד וללא שמירת תוכן בלוג | לקבוע בעל תפקיד ותהליך בדיקה שנתי מתועד |
| הרשאות לפי צורך ותפקיד | אימות JWT ותפקיד בצד השרת; מזכירה אינה מקבלת כלים רפואיים | לבדוק RLS לכל טבלאות המקור ולבצע מבחני חדירה והרשאות |

| התקשרות עם גורם חיצוני | פונקציית שרת מרכזת את כל העיבוד; אין מפתח מודל בדפדפן | הסכם עיבוד/מיקור חוץ לפי תקנה 15, בקרות ספק, מחיקה, אירועים ותתי־מעבדים |
| העברת מידע מחוץ לישראל | המידע מצומצם ומוסר ממזהים לפני ההעברה | לתעד עילת העברה לפי תקנות 2001 ולקבל התחייבות כתובה מתאימה מהנמען |
| עיון ותיקון | דף הפרטיות מספק ערוץ פנייה | לבנות נוהל אימות זהות, זמני מענה ותיעוד הטיפול בבקשות |
| קבלת החלטות בסיוע AI | תוצאות מסומנות כהמלצה; פעולות משמעותיות דורשות אישור אנושי | הדרכת צוות, דגימת איכות ותיעוד חריגים |

## 4. סיכונים ובקרות

| סיכון | חומרה | בקרה |
|---|---:|---|
| זליגת ת״ז, כתובת או פרטי קשר לפרומפט | גבוהה | השחרה כפולה, חסימת שדות לפי מפתח, השחרת פלט, מגבלת אורך |
| זיהוי עקיף מתוך טקסט חופשי | גבוהה | הקשר מצומצם, ללא שמות/קישורים, זיכרון זמני בלבד; בדיקות רגרסיה נדרשות |
| משתמש מתחזה לתפקיד אחר | גבוהה | התעלמות מהתפקיד שנשלח מהדפדפן ואימות מול `staff`/`owners` בשרת |
| המודל מבקש פעולה לא מורשית | גבוהה | רשימת נתיבים לבנה; כלים לקריאה בלבד; אין פונקציות כתיבה; אישור אנושי |
| אבחון או מינון שגויים | גבוהה | הנחיית איסור, סימון ככלי מסייע, ניתוב לצוות רפואי ובדיקות איכות |
| Prompt injection מתוך הודעת לקוח | בינונית–גבוהה | סימון תוכן משתמש כלא מהימן; אין חשיפת הוראות מערכת; אין ביצוע כלי לפי טקסט חופשי |
| לוגים הופכים למאגר תוכן רגיש | גבוהה | אין עמודות לשאלה/תשובה/תוכן; רק מטא־דאטה ותוצאת הפעולה |
| שמירת נתונים אצל ספק המודל | גבוהה | חשבון בתשלום, ביטול שיתוף/לוגים, בחינת ZDR, הסכם מחייב והעברת מידע כדין |

## 5. שערי פריסה מחייבים

אין לסמן את הפריסה כתואמת דין לפני השלמת כל הסעיפים:

- [ ] סיווג רמת אבטחת המאגר לפי התקנות והיקף המידע בפועל.
- [ ] בדיקת חובת רישום או הודעה לרשות לאחר תיקון 13.
- [ ] בדיקת חובת מינוי ממונה הגנת פרטיות לפי פעילות והיקף המאגר.
- [ ] השלמת פרטים משפטיים אמיתיים בדף הפרטיות ובמסמך הגדרות המאגר.
- [ ] חתימת הסכם עיבוד עם Supabase ועם ספק ה־AI, כולל תתי־מעבדים, מחיקה, אירועי אבטחה ומטרת שימוש.
- [ ] תיעוד עילת ההעברה מחוץ לישראל והתחייבות הנמען להגנת המידע.
- [ ] שימוש בתכנית ספק שאינה משתמשת בקלט/פלט לאימון, ביטול שיתוף נתונים ובחינת Zero Data Retention.
- [ ] פריסת המיגרציה, הפונקציה והסודות בצד השרת בלבד.
- [ ] בדיקת RLS והרשאות בארבעה תפקידי צוות ובעלים, כולל ניסיונות גישה אסורים.
- [ ] סקר סיכונים, מבדק חדירות ונוהל אירוע אבטחה ודיווח.
- [ ] נוהל בדיקת לוגים ושמירתם למשך התקופה הנדרשת.
- [ ] נוהל בקשות עיון ותיקון ובדיקה שנתית של מידע עודף.
- [ ] הדרכת משתמשים והגדרה ברורה שאין להסתמך על VetBot בחירום.

## 6. החלטת תכנון

המערכת בנויה כך שהערך היומיומי מתקבל קודם כול ממנוע מקומי ונתונים מצומצמים. שימוש במודל חיצוני הוא שכבה משלימה בלבד. אם תנאי הספק, ההסכם או עילת ההעברה אינם מאושרים — ניתן להשאיר את התדריך המקומי פעיל ולכבות את הקריאות החיצוניות בלי לשבור את MyVet.

## 5. בדיקות שחייבות להתווסף בשלב 1

### Integration מול סביבת בדיקות

1. קריאה ל־`ai-assistant` עם admin, vet, nurse, secretary ו־owner.
2. חסימת JWT חסר/פגום, role לא פעיל ו־owner מחוץ ל־portal.
3. יצירה, דחייה, אישור, תפוגה ואישור כפול של כל action type.
4. שינוי מצב בין preview לאישור: slot נתפס, role השתנה, רשומה נמחקה.
5. owner A מול pet/appointment/conversation של owner B.
6. בדיקת כל טבלה וכל CRUD עם anon, לא רק SELECT בשבע טבלאות.
7. בדיקת כל `SECURITY DEFINER` עם anon ו־authenticated לא מורשה.

### AI/Security

1. Prompt injection בשאלה, הודעת DigitalCare, knowledge ומסמך עתידי.
2. ניסיון לחשוף system prompt, secret, SQL או מידע ממקור אחר.
3. JSON חסר, שדות לא צפויים, enum לא תקין ופלט ארוך.
4. timeout, 429, 5xx, provider outage ו־fallback בין מודלים.
5. rate limit, concurrency, replay ו־cost ceiling.
6. בדיקת redaction למזהים מספריים פנימיים, שמות עקיפים וטקסט רפואי נדיר.

### E2E מוצר

1. פתיחה ושאלה בכל שמונת מצבי VetBot.
2. קביעת תור פיזי ווידאו דרך הבוט, כולל פרטים חסרים ואישור.
3. אישור/דחייה UI של פעולה והודעת הצלחה/כשל אמינה.
4. fallback מקומי ללא אובדן השאלה בכל מסך.
5. נגישות, RTL, mobile ו־desktop של drawer ותשובה מובנית.

## 6. תנאי מעבר לשלב 2

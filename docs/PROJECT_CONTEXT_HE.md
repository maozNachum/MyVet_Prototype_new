# MyVet — הקשר מלא וארכיטקטורת מוצר

עודכן: 16.07.2026  
מטרת המסמך: לאפשר למפתח או ל-Codex חדש להבין את הפרויקט לפני שינוי קוד.

## 1. מהו MyVet

MyVet הוא פרויקט גמר המדמה מערכת מידע אמיתית למרפאה וטרינרית. המערכת מחברת בין עבודת הצוות הקליני והתפעולי לבין בעל החיים ובעליו, דרך בסיס נתונים משותף ופורטל לקוחות.

המוצר בנוי משני אזורים:

- **מערכת צוות** — דשבורד, יומן תורים, לקוחות, מטופלים, תיק רפואי, אשפוזים, מעבדה, מלאי, מרפאה דיגיטלית ודוחות.
- **פורטל לקוחות** — חיות, תורים, מרפאה דיגיטלית, מסמכים, התראות, תשלומים ופרופיל.

VetBot משולב בשני האזורים כשכבת סיוע תפעולית וקלינית מוגבלת, עם צמצום מידע ואישור אנושי.

## 2. משתמשים והרשאות מוצר

### מנהל מרפאה — `clinic_admin`

- גישה לכל אזורי הצוות.
- ניהול תורים וזמינות לקוחות.
- גישה רפואית, תפעולית ופיננסית.
- ניהול ידע VetBot והרשאות לפי ה-RLS בפועל.

### וטרינר — `vet`

- תיק רפואי, טיפולים, מעבדה ואשפוזים.
- יומן תורים, לקוחות, מלאי ודוחות.
- גישה לדוחות פיננסיים לפי `staffAuth.ts`.

### אח/ות — `nurse`

- תיק רפואי, טיפולים, אשפוזים, מעבדה ומלאי.
- אין גישה לדף הדוחות דרך guard הנוכחי.
- שיחה פנימית/תפעולית בהתאם לכללי `staffAuth.ts`.

### מזכיר/ה — `secretary`

- לקוחות, תורים, שירות, מלאי ודוחות תפעוליים.
- אין עריכת רשומה רפואית.
- אין דוחות פיננסיים.

### בעלים — `owner`

- נכנס דרך `/portal` ורואה רק רשומות השייכות לפרופיל המאומת שלו.
- יכול לקבוע תור מתוך שעות פנויות, לצפות בתורים, להזיז/לבטל לפי ההרשאות, לפתוח פנייה, לקרוא מסמכים והתראות ולראות חיובים.

חשוב: בדיקות UI אינן מנגנון הרשאה. ההרשאה האמיתית נאכפת ב-Supabase RLS ובפונקציות שרת.

## 4. דשבורד הצוות

הדשבורד נועד להיות מרכז בקרה ולא אוסף כפול של מדדים.

- ברכה ופעולות מרכזיות.
- מדדים עליונים ממידע אמיתי ב-Supabase.
- כרטיס כחול מרכזי של מצב הטיפול הנוכחי/נושאים הדורשים פעולה.
- תורים להיום עם הדגשת התור הבא ותורים שעברו במראה מעומעם.
- מונה VetBot מציג כמה נושאים דורשים בדיקה.
- Realtime מרענן שינויים בתורים ובישויות תפעוליות מרכזיות.

קבצים חשובים:

- `src/app/pages/Dashboard.tsx`
- `src/app/components/ClinicFlowboard.tsx`
- `src/app/components/SmartWorklist.tsx`
- `src/app/components/ai/PageAssistants.tsx`

## 5. תורים וזמינות

### תור שנקבע על ידי צוות

- נוצר דרך `NewAppointment.tsx` ו-`AppointmentStore.tsx`.
- דחיפות מוצגת כרגיל או חירום בלבד.
- יש לבדוק חפיפה, זמן עתידי ונתוני חובה.

### תור שנקבע על ידי בעלים

הזרימה נמצאת ב-`OwnerBookAppointment.tsx`:

1. בחירת חיה, סיבת ביקור וסוג תור פיזי/וידאו.
2. קריאת `myvet_available_slots` לקבלת שעות פנויות בלבד.
3. סינון נוסף מול תורי בעל החשבון שכבר נטענו בפורטל.
4. רענון זמינות לפני מעבר לסיכום.
5. קריאת `myvet_owner_book_appointment` לשמירה אטומית.
6. אם שעה נתפסה בינתיים, חוזרים לבחירת שעה עם הודעה ברורה.

ברירות המחדל:

- ראשון–חמישי: 08:00–17:00.
- שישי: 08:00–14:00.
- שבת: סגור.
- משך slot ברירת מחדל: 30 דקות.

הצוות מנהל שעות, קיבולת וחסימות דרך `ClinicAvailabilitySettings.tsx` ו-`clinicAvailability.ts`.

## 6. המרפאה הדיגיטלית

`DigitalCare.tsx` מנהל:

- תורים לעבודה: דורש טיפול, ממתין לבעלים, פעילות וארכיון.
- סטטוס אוטומטי לפי ההודעה האחרונה והמצב, במקום תחזוקה ידנית שגרתית.
- דחיפות UI בשתי רמות: רגיל/דחוף. ערכי `high` ישנים מנורמלים כדחופים.
- העברה לארכיון ושחזור.
- הודעות, קבצים וקישורי וידאו.
- יצירת/הדבקת Google Meet, שליחה ללקוח ופתיחת השיחה.
- סיכום שיחת וידאו ושמירת רשומה רפואית מסוג `video_consultation` לאחר אישור צוות.

## 7. פורטל הלקוחות

`ClientPortal.tsx` הוא מסך גדול המחולק ל-views פנימיים:

- בית.
- תורים: צפייה, קביעה, הזזה וביטול.
- דיגיטל: פניות, הודעות וקישורי וידאו.
- החיות שלי: כרטיס חיה, תיק רפואי, חיסונים ומסמכים.
- תשלומים: חיובים פתוחים והיסטוריה; אם אין חיובים מוצגת empty state ברורה.
- התראות ותזכורות.
- פרופיל.

ב-mobile קיימים header, תפריט, ניווט תחתון וכפתור VetBot צף. כל שינוי בפורטל חייב להיבדק ברוחב טלפון וגם desktop.

תשלום בפורטל הוא הדגמה בלבד. אין לעדכן `payments` מהדפדפן עד שתהיה אינטגרציית סליקה עם webhook מאומת.

## 8. תיק רפואי, מעבדה ואשפוז

- `MedicalStore.tsx` מרכז פעולות ורשומות רפואיות.
- `TreatmentModal.tsx` ופעולות post-save משלבות סיכום, מרשם, מעבדה ופרסום לבעלים.
- `LabStore.tsx`, `LabOrders.tsx` ו-`LabResultsPanel.tsx` מנהלים הזמנה, סטטוס ותוצאות.
- `Hospitalizations.tsx` ו-`HospitalizationModal.tsx` מנהלים אשפוז פעיל והיסטוריה.
- מסמכים ותמונות רפואיות נשמרים ב-storage פרטי ונפתחים דרך signed URLs.

## 9. דוחות

`Reports.tsx` משתמש ברכיבים תחת `components/reports` וב-`reportMetrics.ts`:

- סקירת BI.
- הכנסות וחיובים.
- ניצול צוות.
- היענות לקוחות.
- בקרת מלאי.
- מגמות אפידמיולוגיות.
- VetBot לדוחות דרך כפתור מרכזי אחד.

יש לכבד `canAccessReportsPage`, `canViewFinancialReports` ו-`canViewOperationalReports`.

## 10. VetBot

VetBot משולב בדשבורד, יומן, דיגיטל, מלאי, תיק רפואי, לקוחות, דוחות ופורטל.

הזרימה:

1. `aiContextBuilder.ts` יוצר הקשר מצומצם.
2. `aiProactiveEngine.ts` יכול ליצור תדריך מקומי ללא ספק חיצוני.
3. `aiSanitizer.ts` משחיר מידע בדפדפן.
4. `aiClient.ts` קורא ל-Edge Function.
5. `supabase/functions/ai-assistant/index.ts` מאמת JWT ותפקיד, משחיר שוב, מפעיל כלי קריאה בלבד וקורא ל-Gemini.
6. `AiStructuredAnswer.tsx` מציג תשובה, ממצאים ופעולות מאושרות.
7. נשמר audit metadata בלבד ומשוב ללא תוכן השיחה.

VetBot אינו מבצע כתיבה אוטונומית. כל suggested action משמעותי דורש אישור אנושי.

## 12. מצב בדיקות

- `npm run test:privacy` — בדיקות הסרת מזהים.
- `npm run test:vetbot` — פרטיות, RLS, תורים, טיפוגרפיה ו-regression.
- `npm run test:anon-access` — שומר סף נגד גישה אנונימית; דורש סביבת Supabase מתאימה.
- `npm run build` — בניית Vite ל-production.

## 13. נקודות שדורשות זהירות

- חלק מהטבלאות נוצרו לפני המיגרציות שנמצאות בריפו; המיגרציות המקומיות הן שכבת אבטחה/הרחבה ולא dump מלא של schema המקור.
- `ClientPortal.tsx`, `DigitalCare.tsx`, `Dashboard.tsx` ו-`Patients.tsx` גדולים; יש לבצע שינויים ממוקדים.
- LocalStorage משמש להצגת session metadata של צוות, אך הרשאות אמיתיות חייבות להישען על Supabase.
- אין להסיק שהדגמה חזותית שווה להגנת Production. יש להשלים את שערי הפריסה במסמכי ה-runbook וה-DPIA.

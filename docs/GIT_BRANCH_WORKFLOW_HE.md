# נוהל עבודה בענפי Git

מטרת הנוהל היא לאפשר למעוז ולניסן לעבוד במקביל בלי לאבד שינויים ובלי לפרוס קוד שלא עבר בדיקה.

## תפקידי הענפים

- `master` — גרסת Production בלבד. אין לעבוד עליו ישירות ואין למזג אליו ללא אישור מפורש ובדיקות קבלה.
- `Full_Demo` — ענף האינטגרציה המשותף והמקור לכל משימה חדשה. אין לפתח עליו ישירות.
- ענף משימה — ענף קצר שיוצא מ־`Full_Demo`, לדוגמה `maoz/privacy-requests` או `nisan/owner-claim`.

## זרימת עבודה לכל משימה

1. לעדכן את `Full_Demo` מהמאגר המרוחק ולוודא שאין שינויים מקומיים לא צפויים.
2. ליצור ממנו ענף משימה אחד, עם שם הבעלים ותיאור קצר.
3. לשמור בענף רק שינויים השייכים למשימה. אין לצרף קובצי פלט, קבצים זמניים, צילומי מסך או סודות.
4. לפני שילוב, לעדכן את ענף המשימה מול `Full_Demo`, לפתור התנגשויות ולהריץ את בדיקות הפרויקט הרלוונטיות.
5. לבצע ביקורת של האדם השני על ההבדלים, ואז למזג ל־`Full_Demo`.
6. לבדוק שוב את `Full_Demo`, לדחוף אותו ולמחוק את ענף המשימה המקומי והמרוחק.

## עבודה מקבילה

- כל משימה שייכת לאדם אחד, והוא הבעלים היחיד של הקבצים החופפים בזמן העבודה.
- אם שתי משימות צריכות לשנות אותו קובץ, קובעים סדר שילוב מראש; המשימה השנייה מתעדכנת רק לאחר שהראשונה מוזגה.
- מיגרציות מקבלות חותמת זמן ייחודית. אין לשנות מיגרציה שכבר הוחלה; מוסיפים מיגרציית המשך.
- אין להחיל מיגרציות, לפרוס פונקציות או לשנות Production מתוך ענף משימה.

## תנאי מעבר מ־`Full_Demo` ל־`master`

- כל הבדיקות הנדרשות עברו וההבדלים המלאים נבדקו.
- מיגרציות ופעולות ידניות מתועדות ונבדקו בסביבה שאינה Production.
- אין קבצים זמניים, סודות או שינויים שאינם קשורים לגרסה.
- התקבל אישור מפורש למיזוג ולפריסה.
